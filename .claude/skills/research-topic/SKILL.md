# AI開発トピックのリサーチ

このスキルは Zenn 記事の執筆に耐える品質で AI 開発関連トピックをリサーチする。
リアルタイムのトレンド着火点 → 一次ソース検証 → 学術/インパクト分析 の3層構造で進める。

## 起動条件

- ユーザーがリサーチ・調査・トレンド収集を依頼したとき
- 記事執筆前のネタ集め・裏取り段階
- 引数 `topic`（必須）と `depth`（任意: quick / standard / deep）を受け取る

## リサーチ原則

- **一次ソース優先**: 公式blog / docs / changelog / GitHub / arXiv を最優先
- **二次情報は裏取り前提**: ニュース記事・個人ブログは必ず一次ソースで検証
- **検証できない定量データは記録しない**（CLAUDE.md ルール準拠）
- **既存記事チェック**: `articles/` 配下に同テーマがないか先に確認

## リサーチ深度

| 深度 | 想定時間 | スコープ |
|---|---|---|
| quick | ~5分 | 一次ソース1-2件 + 概要把握 |
| standard | ~15分 | 3階層フルカバー + 実行検証 |
| deep | ~30分+ | 学術論文・統計データ・パラドックス分析まで |

省略時は `standard`。

## 手順

### 0. 事前チェック

- `articles/` を grep して同テーマの既存記事を確認
- 既存記事がある場合は「更新」前提で差分リサーチに切り替え

### 1. リアルタイム着火点の発見（鮮度レイヤー）

並列で以下を WebSearch する：
- `<topic> 2026` （英語）
- `<topic> 最新 2026` （日本語）
- `<topic> github trending` または `<topic> hacker news`
- `<topic> X Twitter` （開発者の生の声）

得られたシグナル：話題のリポジトリ、リリース、議論されている pros/cons をメモ。

### 2. 一次ソース検証（Tier 1）

着火点で得たキーワードを元に：
- 該当ツール・ライブラリの **公式blog / docs / changelog** を WebFetch
- **GitHub リポジトリ**の README / Issues / Discussions / Releases を `gh` CLI で確認
- **API リファレンス** / 公式サンプルコードを参照
- 可能なら **CLI を実際に実行**して挙動を確認（`Bash` ツール）

各事実は出典URLとセットで記録。

### 3. 学術・実証データ（Tier 2、deep のみ必須）

- **arXiv**（cs.AI / cs.SE）で関連論文を検索
- **METR**（metr.org）の RCT 研究
- **Stanford HAI AI Index** の年次レポート
- **JetBrains AI Pulse Survey** などの大規模調査

定量データ（X% 高速化、Y時間短縮 等）は必ず出典・調査時期・サンプルサイズを併記。

### 4. インパクト分析（記事のフック作り）

以下の観点で「読者の興味を引く切り口」を抽出：
- **採用率・利用率**（業界全体の数値）
- **生産性の実数**（時短・PR数・サイクルタイム）
- **パラドックス・逆説**（「AI使ってるのに〜」系）
- **社会的影響**（雇用・GDP・スキル要件の変化）
- **コスト・リスク**（issue増加率、セキュリティ、レビュー負荷）

### 5. コミュニティ動向（Tier 3、参考程度）

- Reddit（r/LocalLLaMA, r/ClaudeAI, r/programming）
- Hacker News のコメント傾向
- Zenn / Qiita / dev.to の既出記事（重複防止）
- Awesome系リポジトリ

### 6. 成果物の出力

以下のフォーマットでユーザーにレポート：

```markdown
# リサーチレポート: <topic>

## 1行サマリ
（記事のフックになる1文）

## 一次ソース（検証済み）
- [タイトル](URL) — 要点
- ...

## 主要な事実・データ
- 事実1（出典: URL, 調査時期）
- ...

## 記事のフック候補
- 切り口A: 〜
- 切り口B: 〜
- 切り口C: 〜

## 既出記事との差別化ポイント
- Zenn/Qiita の既存記事: ...
- 本記事で書ける新規性: ...

## 検証で実行したコマンド/手順
- `<command>` → 結果
- ...

## 未検証・要追加調査項目
- ...
```

### 7. 次アクションの提案

レポート末尾で、以下を1-2行で提案：
- そのまま `publish-article` スキルでZenn記事化するか
- 追加で深掘りするポイントがあるか
- `schedule` で定点観測エージェントを組むべきか

## 注意事項

- WebSearch の結果を**そのまま貼り付けない**。必ず一次ソースに当たって裏取りする
- インストール数・ユーザー数等の数値は、公式発表または信頼できる統計レポート以外からは引用しない
- 検証中に矛盾するデータが出てきたら、両方記録して「未確定」として扱う
- 日本語ソース・英語ソースの両方をバランスよく集める
