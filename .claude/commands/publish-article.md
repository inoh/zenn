Zennの技術記事を作成してください。

## 手順

### 0. 事前チェック

- `articles/` ディレクトリを確認し、同テーマの既存記事がないかチェックする
- 既存記事がある場合は新規作成せず、既存ファイルを更新する

### 1. 記事の企画

ユーザーが指定したテーマ「$ARGUMENTS.topic」について、以下を決定してください：

- **タイトル**: 具体的で検索されやすいタイトル
- **emoji**: 記事の内容に合った絵文字1つ
- **topics**: 関連する技術タグ（最大5つ、小文字英数字）
- **スラッグ**: `YYYY-MM-DD-slug-name` 形式（今日の日付を使用）

企画内容をユーザーに提示し、承認を得てから次のステップに進んでください。

### 2. 記事の執筆

作業ブランチを作成してから記事を書く。

```bash
git checkout -b article/{スラッグ}
```

以下のフォーマットで記事ファイルを作成してください：

**ファイルパス**: `articles/{スラッグ}.md`

```markdown
---
title: "タイトル"
emoji: "絵文字"
type: "tech"
topics: ["topic1", "topic2"]
published: true
---

## はじめに

（導入文）

## 本文セクション

（内容）

## まとめ

（まとめ）
```

執筆のガイドライン：
- 実践的で具体的なコード例を含める
- ハマりどころや注意点を共有する
- 読者が再現できるように手順を明確に書く
- 見出しで構造化し、読みやすくする
- **Web検索の結果をそのまま事実として書かない。CLI実行・GitHubリポジトリ・公式ドキュメント等の一次ソースで必ず検証する**
- **検証できない定量データ（インストール数等）は記載しない**

### 3. PRの作成

記事をコミットし、PRを作成してユーザーにレビューしてもらう。

```bash
git add articles/{スラッグ}.md
git commit -m "Zennに「{タイトル}」の記事を追加"
git push -u origin article/{スラッグ}
gh pr create --title "記事: {タイトル}" --body "## 概要\n記事の新規追加\n\n## 確認事項\n- [ ] 内容の正確性\n- [ ] リンク切れ\n- [ ] frontmatter"
```

PRのURLをユーザーに共有し、レビューを依頼する。

### 4. マージと公開

**ユーザーがPRを承認した後**、マージを実行する。mainブランチへのpushでZenn連携により自動公開される。

```bash
gh pr merge --merge
```
