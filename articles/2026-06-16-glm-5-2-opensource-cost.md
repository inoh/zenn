## はじめに

2026年6月13日、中国のZhipu AI（Z.ai）がコーディング特化の新フラッグシップ「GLM-5.2」を発表しました。「MITライセンスでオープンソース化」「100万トークンのコンテキスト」「Claude Codeにそのまま挿せる」といった見出しがSNSやニュースを駆け巡り、私も「オープンソースになったなら重みを落として試そう」とHuggingFaceを開きました。

ところが発表直後（6月16日時点）は、**GLM-5.2のモデルデータ（いわゆる「重み」）はどこにも見つかりませんでした。** 各種報道は「オープンソース化」と書いていましたが、実際に配布が始まったのはその数日後です。

:::message
**「重み（オープンウェイト）」とは？**
ここでいう「重み（weights）」は、学習済みAIモデルの中身そのものにあたる巨大な数値データのことです。これを誰でもダウンロードできる形で配布することを「オープンウェイト（open weights）」と呼び、一般に「モデルがオープンソース化された」と言うときはこの重みファイルの公開を指します。重みが手元にあれば、自分のPCやサーバーでモデルを動かせます。逆に重みが無ければ、提供元のAPIやサービス経由でしか使えません。
:::

この記事では、まず「GLM-5.2はオープンソースになった」という言説を一次ソースで検証した経緯を整理し、そのうえで**実際に公開された重みを手元で検証した結果**と、「では今、課金を最小限にしてどう試せるのか」「コストはどうなっているのか」をまとめます。

:::message
**検証の範囲について。** 本記事では、公開された重みファイル（`config.json`・シャード構成・総サイズ）やAPIエンドポイントの稼働を**手元で実際に確認**しました。一方、GLM-5.2に実際にプロンプトを投げて応答させる推論そのものは、有料APIキーが前提となるため本記事では行っていません（後述）。実機の応答ログは、APIキーを用意でき次第追記します。
:::

## GLM-5.2とは何か

GLM-5.2はGLM-5系列の3番目のメジャーイテレーションで、エージェント的なコーディング（agentic coding）と長時間にわたるソフトウェアエンジニアリングに最適化されたモデルです。公開された重みの `config.json` を実際に取得して確認したスペックは以下のとおりです。

| 項目 | 内容 |
|---|---|
| 発表日 | 2026年6月13日 |
| 重み公開日 | 2026年6月17日（MIT） |
| アーキテクチャ | 744B MoE（`glm_moe_dsa`／78層／ルーテッドエキスパート256中8がアクティブ＋共有1） |
| コンテキスト長 | 1,048,576トークン（`max_position_embeddings`） |
| 最大出力 | 131,072トークン（公式docs表記は128K） |
| モデルコード（API） | `glm-5.2` |
| ライセンス | MIT |

744B MoEというパラメータ規模は、前世代のGLM-5から引き継いだものです。GLM-5の公式READMEには「GLM-4.5の355B（アクティブ32B）から744B（アクティブ40B）へスケールし、事前学習データを23Tから28.5Tトークンへ拡大した」と記載されています（[zai-org/GLM-5](https://github.com/zai-org/GLM-5)）。

GLM-5.2では新アーキテクチャ「IndexShare」が導入され、公式READMEによれば**1Mコンテキスト長でトークンあたりのFLOPsを2.9倍削減**し、投機的デコード（speculative decoding）の受理長も最大20%向上させています。

## 「オープンソース化」の真相：告知 → 数日後に重み公開

ここが本記事の核心です。発表直後は「オープンソースになった」という見出しが先行していましたが、**実際にダウンロードできる重みファイルが置かれたのは数日後**でした。

### 6月16日時点：重みはまだ無かった

発表から数日間、一次ソースを確認しても重みは見つかりませんでした。

- HuggingFaceに `zai-org/GLM-5.2` のモデルページが存在しない
- GitHubの公式リポジトリにGLM-5.2のタグ・リリースが無い（`gh api repos/zai-org/GLM-5/tags` が空）
- 公式blog `z.ai/blog/glm-5.2`、docs `docs.z.ai/guides/llm/glm-5.2` がいずれも404

各種報道を総合すると、6月13日の発表で即日利用可能になったのは「GLM Coding Plan」経由のみで、単体API・チャット版・MITオープンウェイトは「翌週公開予定」とアナウンスされていました（[PC Watch](https://pc.watch.impress.co.jp/docs/news/2116962.html)）。

### 6月17日：重みがMITで正式公開された

予定どおり、**2026年6月17日にHuggingFace上で重みが公開**されました。一次ソースで実際に確認した内容は次のとおりです。

- [zai-org/GLM-5.2](https://huggingface.co/zai-org/GLM-5.2) … **公開済み・MITライセンス**（safetensorsシャード282個・全291ファイル、最終更新 `2026-06-17T09:31`）
- [zai-org/GLM-5.2-FP8](https://huggingface.co/zai-org/GLM-5.2-FP8) … FP8量子化版も公開
- GitHubの [zai-org/GLM-5](https://github.com/zai-org/GLM-5) READMEがタイトルごと「GLM-5.2 & GLM-5.1 & GLM-5」に更新
- 公式blog `z.ai/blog/glm-5.2`・docs `docs.z.ai/guides/llm/glm-5.2` が404から200に

実際に `config.json` を取得すると、`model_type: glm_moe_dsa` / 78層 / ルーテッドエキスパート256・アクティブ8 / `max_position_embeddings: 1048576` と、公称スペックどおりの中身であることを確認できました。

```bash
$ curl -s https://huggingface.co/zai-org/GLM-5.2/raw/main/config.json | \
    python3 -c "import sys,json; d=json.load(sys.stdin); \
    print(d['model_type'], d['num_hidden_layers'], d['max_position_embeddings'])"
glm_moe_dsa 78 1048576
```

つまり「GLM-5.2がオープンソースになった」は、**発表時点では「告知」、6月17日に晴れて事実**になった、という時系列で捉えるのが正確です。発表直後に「オープンソースになったらしいからモデルを探す」と動くと、私のように空振りします。

## 「オープンソース＝ローカルで気軽に動く」ではない

重みが公開されたので「自分のPCで動かせるのでは」と思うかもしれませんが、ここに大きな落とし穴があります。**MITライセンスで誰でもダウンロード・改変・商用利用できること（＝オープンソース）と、手元のマシンで動かせることは別物**です。

公開された全シャードのサイズを実際に合計してみました。

| 形式 | 重み総サイズ（実測） | 必要VRAMの目安 |
|---|---|---|
| BF16（標準・`zai-org/GLM-5.2`） | **約1,507GB（1.51TB）** | H100/H200（80〜141GB）が概ね13〜19枚 |
| FP8（`zai-org/GLM-5.2-FP8`） | **約756GB** | 同7〜10枚 |
| 4bit量子化（GGUF想定・理論値） | 約400GB前後 | 80GB級GPU 5枚以上、またはCPUオフロード（低速） |

744B MoEなので推論時に実際に計算へ使われるのはアクティブ約40B相当ですが、**MoEは「どのエキスパートが選ばれるか分からない」ため、重みは全部メモリに載せておく必要があります**。したがってサイズは縮みません。例えばRTX 5090（VRAM 32GB）でFP8の756GBを載せるだけでも、理屈上24枚以上が必要です。これは個人PCではなくデータセンター級の構成です。さらに1Mコンテキストを使うと、KVキャッシュが数百GB単位で上乗せされます。

**結論：オープンソース化されても、現実的な「試す」入口は引き続きAPI（Coding Planまたは従量課金）です。** 「オープンソース＝無料で気軽に動かせる」とイコールではない点は、改めて数字で押さえておきましょう。

## では今、どう試すのか

ローカル実行が非現実的な以上、今すぐGLM-5.2を試す現実的な経路は**GLM Coding PlanまたはZ.aiの従量APIキーを使う**方法です。

GLM系モデルの鍵は **Anthropic互換エンドポイント**（`https://api.z.ai/api/anthropic`）を提供している点です。Claude Codeの接続先を差し替えるだけでGLM-5.2をバックエンドに使えます。これがGLM系モデルが「Claude Codeに挿せる」と言われる仕組みです。なお、このエンドポイントが現在稼働していることは確認済みで、キー無しでリクエストを投げると認証エラー（`type:1001`）が返ります。

### Claude Codeに挿す設定

環境変数で接続先と認証トークンを差し替えます。モデルコードは公式docsで `glm-5.2` であることを確認済みです。

```bash
# Z.aiで発行したAPIキーを使う
export ANTHROPIC_AUTH_TOKEN="（あなたのZ.ai APIキー）"
export ANTHROPIC_BASE_URL="https://api.z.ai/api/anthropic"

# Claude Codeが使うモデルスロットをGLM-5.2に割り当てる
export ANTHROPIC_DEFAULT_SONNET_MODEL="glm-5.2"
```

この状態で `claude` を起動すると、Sonnetスロットの処理がGLM-5.2に向きます。

疎通確認だけなら、Anthropic互換APIに直接cURLを投げる方法もあります。

```bash
curl -s https://api.z.ai/api/anthropic/v1/messages \
  -H "x-api-key: $ANTHROPIC_AUTH_TOKEN" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"glm-5.2","max_tokens":100,"messages":[{"role":"user","content":"あなたのモデル名は？"}]}'
```

:::message
上記の実機での応答ログ（疎通・Claude Code連携の実行結果）は、有料APIキーを用意でき次第、本記事に追記します。本記事の段階では、エンドポイントの稼働とモデルコードの確認までを実機検証済みとして提示しています。
:::

## 気になるコストの話

GLM-5.2まわりの料金は「プラン課金」と「従量API」の2系統で考えます。重み公開にあわせて、**従量APIの価格も公式に公表されました**。

### ① 従量API（公開済み）

GLM-5.2の従量課金価格は、公式の価格表（[docs.z.ai/guides/overview/pricing](https://docs.z.ai/guides/overview/pricing)、per 1Mトークン）で確認できます。**前世代のGLM-5.1と同額**でした。第三者の集計（[OpenRouter](https://openrouter.ai/z-ai/glm-5.2)）でも同じ価格・1,048,576トークンのコンテキストが掲載されており、独立に裏が取れます。

| モデル | 入力 | キャッシュ入力 | 出力 |
|---|---|---|---|
| **GLM-5.2** | **$1.40** | **$0.26** | **$4.40** |
| GLM-5.1 | $1.40 | $0.26 | $4.40 |
| GLM-5 | $1.00 | $0.20 | $3.20 |

フロンティアの商用モデルと比べると桁違いに安い水準です。執筆当初は未公表でしたが、重み公開とあわせて確定しました。

### ② GLM Coding Plan（サブスク）

GLM-5.2は全プランに追加料金なしで含まれます。公式ドキュメントにも「All plans support GLM-5.2 ...」と明記されています（[docs.z.ai/devpack/overview](https://docs.z.ai/devpack/overview)）。利用上限はトークン量ではなく「プロンプト数」で管理されます。

| プラン | 5時間あたり | 週あたり |
|---|---|---|
| Lite | 約80プロンプト | 約400プロンプト |
| Pro | 約400プロンプト | 約2,000プロンプト |
| Max | 約1,600プロンプト | 約8,000プロンプト |

料金については、公式ドキュメントに **「Starting at just 18 USD per month（月18ドルから）」** と記載されています。

:::message alert
第三者のまとめサイトでは「Lite $10前後 / Pro $15〜19 / Max $80程度」といった金額がよく見られますが、割引・課金サイクル・地域差・情報の鮮度で変動します。**正確な金額は必ずZ.aiの公式サブスクリプションページで確認してください。** 本記事では断定を避けます。
:::

### ③ セルフホスト：公開後も相応のコスト

前述のとおり重みは1.51TB（FP8でも756GB）規模です。量子化を前提にしても相応のVRAMとストレージが必要で、「月数十ドルのプランで試す」とは別次元のコストになります。

## まとめ

- **「GLM-5.2がオープンソースになった」は、発表時点では「告知」、2026年6月17日に晴れて事実になりました**。HuggingFaceにMITライセンスで重みが公開され、`config.json`・シャード構成も実物を確認済みです。
- **オープンソース化されても、現実的に試す入口はAPI**。重みは実測でBF16 1.51TB／FP8 756GBあり、ローカル実行はデータセンター級のGPUが必要です。「オープンソース＝気軽に無料で動く」ではありません。
- **Claude Codeへの挿し方は接続先の差し替えのみ**。モデルコードは `glm-5.2`、エンドポイントの稼働も確認済みです（実機の応答ログはキー用意後に追記予定）。
- **コストは従量APIが公表され、GLM-5.1と同額の入力$1.40／キャッシュ$0.26／出力$4.40**。Coding Planは月18ドルから（正確な金額は公式ページで要確認）。
- 発表ラッシュの時期は、**「オープンソースになった」という見出しを真に受ける前に、HuggingFace・GitHubに実物（重みファイル）があるかを自分の目で確認する**のが効きます。今回はまさに、告知から数日のタイムラグがありました。
